# 🎫 活动票务现场核销漏斗报表系统

用于复盘活动票务现场核销问题的交互式分析看板。基于 **Streamlit + Polars + DuckDB + MinIO** 技术栈构建。

---

## ✨ 核心功能

### 🎯 核销漏斗分析
- **五层漏斗**：已出票 → 已支付 → 有效票（扣除退票）→ 已检票入场 → 已出场
- **效率核心指标**：核销率、退票率、失败率、峰值吞吐量、首检/末检时间
- **入场时间分布**：支持 1/5/15 分钟、小时粒度，识别入场瓶颈

### 📊 逐层下钻（从总览到原始数据）
```
总览看板
  ├─ 🏢 赞助清单（赞助商利用率 → 关联票种 → 具体门票 → 闸机原始记录）
  ├─ 💎 票种规则（核销收入矩阵 → 渠道分布 → 门票列表 → 闸机原始记录）
  ├─ 🚪 核销记录（检票口效率 → 人员绩效 → 单条核销详情）
  └─ 📦 闸机原始记录（设备信息、扫描Payload、失败日志、重复检票检测）
```

### ⚖️ 退票争议与任务管理
- 争议工单提交/审核/状态流转
- 新建争议时**自动生成4条关联任务**（核实核销、核对流水、联系用户、归档材料）
- **任务看板**：待执行 / 进行中 / 已完成 三栏视图
- 关联闸机原始记录辅助判断争议真实性
- 处理结论永久归档

### 🛡️ 权限与分享体系（四大角色）
| 模块 | 主办方 | 票务人员 | 检票员 | 观众/外部 |
|------|:---:|:---:|:---:|:---:|
| 总览看板 | ✅ | ✅ | ✅ | ✅ |
| 赞助清单 | ✅ | ✅ | 🔒 | 🔒 |
| 票种规则 | ✅ | ✅ | ✅ | ✅ |
| 核销记录 | ✅ | ✅ | ✅ | 🔒 |
| 闸机原始记录 | ✅ | ✅ | 🔒 | 🔒 |
| 退票争议管理 | ✅ | ✅ | 🔒 | 🔒 |
| 分享链接管理 | ✅ | ✅ | 🔒 | 🔒 |
| **敏感字段**（手机/邮箱/票码/流水） | ✅ | ✅ | 🔒 | 🔒 |

### 🔗 带权限的分享链接
- 按【数据范围 + 允许角色 + 有效期 + 最大查看次数】生成
- SHA256哈希存储，仅创建时显示Token一次
- 链接可随时手动撤销
- **无论是否通过链接访问，敏感字段永远按当前登录角色严格脱敏**

## 🚀 快速启动

### 方式一：一键启动（推荐）
```bash
git clone <repo>
cd MP0416
./start.sh 8501
```

### 方式二：手动启动
```bash
# 1. 安装依赖
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 2. 配置环境变量（可选）
cp .env.example .env

# 3. 创建数据目录
mkdir -p data

# 4. 启动服务
streamlit run app.py --server.port 8501
```

启动后访问 **http://localhost:8501**

### 🧪 首次使用
1. 在左侧边栏 **🧪 模拟数据生成器** 点击 **🎲 生成模拟数据**（选择活动数量，默认2场）
2. 在 **👤 登录模拟** 切换不同角色体验权限差异（Demo账号见下）
3. 在 **🎪 活动选择** 选择具体活动或查看全部

## 🗄️ 数据模型（14张表，DuckDB）

| 表名 | 说明 | 关键字段 |
|------|------|---------|
| `events` | 活动 | 场地、容量、主办方、日期 |
| `sponsors` | 赞助商 | 级别、分配票数、联系方式 |
| `ticket_types` | 票种规则 | 价格、发行量、销售时段、核销规则JSON、关联赞助商 |
| `orders` | 订单 | 金额、渠道、来源、购票人信息 |
| `tickets` | 门票 | 票码、票种、支付/退票状态、座位、持票人 |
| `payments` | 支付流水 | 交易号、方式、退款金额/原因、网关响应JSON |
| `staff` | 工作人员 | 角色、分配检票口、联系方式 |
| `gate_records` | 闸机记录 | 票码、检票口、检票员、出入场时间、失败原因、**设备JSON + 原始扫描Payload** |
| `refund_disputes` | 退票争议 | 类型、原因、处理人、状态、解决方案、最终结论 |
| `notes_tasks` | 任务看板 | 类型、优先级、负责人、截止、状态、完成时间 |
| `processing_conclusions` | 处理结论 | 关联图表、类型（分析/建议/总结）、作者 |
| `share_links` | 分享链接 | Token哈希、允许角色、有效期、查看次数 |
| `users` | 用户 | 角色、可访问活动、联系方式 |

## 🔧 高级功能

### 连接真实 MinIO（可选）
```bash
# 在 .env 中配置
MINIO_ENDPOINT=minio.company.com:9000
MINIO_ACCESS_KEY=your_key
MINIO_SECRET_KEY=your_secret
MINIO_SECURE=true
MINIO_BUCKET=ticket-activity-prod
```

### 接入真实票务/闸机数据
1. 将票务平台导出的 CSV/JSON 放入 MinIO 或本地 `data/`
2. 参考 `src/data/mock_data.py` 的表结构，用 `src/data/database.py` 的 `db.write_df()` 导入
3. 闸机原始记录建议保留 `raw_payload` JSON字段，便于故障排查

### 权限二次开发
- 新增角色：在 `src/auth/permissions.py` 的 `UserRole`、`ROLE_LABELS`、`ROLE_HIERARCHY` 中添加
- 新增敏感字段：在 `SENSITIVE_COLUMNS` 中注册表名和列名即可自动脱敏
- 新增分享范围：在 `VIEW_SCOPES` 中注册，并在 `app.py` 的 `scope_to_page` 增加映射
