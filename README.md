# 长租公寓保洁排班漏斗报表

基于 **Streamlit + Polars + DuckDB + MinIO** 的长租公寓保洁排班漏斗分析系统。

## 功能特性

### 1. 保洁排班漏斗分析
- 漏斗 stages：已排班 → 已发送提醒 → 实际到场 → 完成服务
- KPI 指标卡片（到场率、准时率、完成率、提醒覆盖率、排班总数），全部支持**同环比**对比
- 到场率趋势图（按日期/区域/保洁员/区域+日期分组）
- 各区域到场率对比

### 2. 时段冲突检测
- 按日检测保洁员时段冲突
- 甘特图可视化冲突时段
- 点击冲突行可**跳转**到对应排班明细样本

### 3. 日历明细
- 排班日历视图
- 点击时段可跳转到该条排班的完整明细
- 支持按日期范围和区域筛选

### 4. 到场状态与提醒名单（同环比）
- 指标维度：到场率 / 准时率 / 提醒覆盖率 / 排班总数
- 环比（MoM）和同比（YoY）对比结果 JSON 化展示
- 待提醒名单一览（未发送提醒 + 缺席未到）

### 5. 容量规则说明
- 解释数据口径：保洁员日/周最大单量、单户预估时长、高峰时段、区域配置保洁员数
- 在岗人数、人均任务数、超员人数等容量利用指标
- 各保洁员任务分布明细

### 6. 分享链接与权限
- 按角色限制数据范围：**租客 / 管家 / 维修员 / 财务 / 外部人员 / 管理员**
- 可限制区域、租客编号、有效期
- 外部人员通过分享链接访问，**不可见**支付、合同、租金等敏感字段

### 7. 可审计的数据同步节点
- 数据同步链路拆分为独立可审计节点
- 每个节点：源记录数、目标写入数、执行耗时、状态、错误信息
- 审计日志同时写入 DuckDB（分析）和 MinIO（归档）

## 快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 配置环境变量（可选）

```bash
cp .env.example .env
# 编辑 .env 填入 MinIO、DuckDB 等配置
```

### 3. 启动应用

```bash
streamlit run app.py
```

首次启动会自动生成示例数据（50 公寓 / 50 租客 / 20 保洁员 / ~90 天排班 + 支付 + 合同 + 抄表）。

### 4. 演示账号

| 用户名 | 角色 | 权限说明 |
|--------|------|----------|
| admin | 系统管理员 | 全部权限，可见所有区域、敏感字段 |
| finance_zhang | 财务 | 可见支付、合同、租金等敏感字段 |
| housekeeper_li | 管家 | 仅可见朝阳区数据，不可见敏感字段 |
| maintenance_zhao | 维修员 | 可见全部区域排班，不可见敏感字段 |
| tenant_001 | 租客 | 仅可见 TEN0001 相关数据 |

### 5. 分享链接测试

1. 用 `admin` 登录，进入「🔗 分享链接」标签
2. 选择角色（如外部人员）、有效期，生成 Token
3. 浏览器打开 `http://localhost:8501/?token=<生成的Token>`

## 容量规则（可在 src/config.py 调整）

```python
CAPACITY_RULES = {
    "cleaner_daily_max": 8,        # 保洁员每日最大单量
    "cleaner_weekly_max": 40,      # 保洁员每周最大单量
    "apartment_cleaning_hours": 2, # 单户保洁预估小时数
    "peak_hours": ["09:00", "12:00", "14:00", "17:00"],  # 高峰时段
    "region_cleaners": {           # 各区域配置保洁员
        "东城区": 5, "西城区": 4, "朝阳区": 6,
        "海淀区": 5, "丰台区": 3
    },
}
```
